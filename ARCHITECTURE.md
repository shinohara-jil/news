## 📦 レイヤー構成

### 1. プレゼンテーション層（UI）

**責務**: ユーザーインターフェース、ユーザー操作の受付

**構成要素**:
- `app/page.tsx` - ホームページ
- `app/admin/page.tsx` - 管理画面（手動実行UI）
- `app/layout.tsx` - 共通レイアウト

### 2. API層（Next.js API Routes）

**責務**: HTTPリクエストの処理、認証、ビジネスロジックの呼び出し

**構成要素**:
- `app/api/fetch-news/route.ts` - ニュース取得・保存API
- `app/api/news/route.ts` - ニュース読み取りAPI
- `app/api/auth/route.ts` - OAuth認証URL生成
- `app/api/auth/callback/route.ts` - OAuth認証コールバック

### 3. ビジネスロジック層（lib/）

**責務**: コアロジック、外部API連携、データ変換

**構成要素**:
- `lib/rss.ts` - RSS取得
- `lib/gemini.ts` - AI画像生成
- `lib/classify.ts` - カテゴリ分類
- `lib/ogp.ts` - OGP画像取得
- `lib/drive.ts` - Google Drive連携
- `lib/sheets.ts` - スプレッドシート書き込み
- `lib/sheets-read.ts` - スプレッドシート読み込み

### 4. 外部サービス層

**責務**: 外部APIとのインテグレーション

**構成要素**:
- Google News RSS
- Gemini API（Google AI）
- Google Sheets API
- Google Drive API

## 🚀 スケーラビリティとパフォーマンス

### 現在の制限事項

1. **実行時間**: Vercel無料プラン = 5分
2. **同時処理**: 1記事ずつ順次処理（並列処理なし）
3. **レート制限**: Gemini APIの制限に依存

### 将来の拡張案

#### 1. 並列処理の導入

```typescript
// 現在: 順次処理
for (const item of items) {
  await processItem(item);
}

// 改善案: 並列処理
const results = await Promise.allSettled(
  items.map(item => processItem(item))
);
```

#### 2. キューシステムの導入

```
GitHub Actions
     │
     ▼
  Job Queue (Redis/SQS)
     │
     ▼
  Worker Processes（複数）
     │
     ▼
  Database/Spreadsheet
```

#### 3. キャッシュ層の追加

```
Client Request
     │
     ▼
  CDN Cache (Vercel Edge)
     │ Cache Miss
     ▼
  Next.js Cache (ISR)
     │ Cache Miss
     ▼
  API / Database
```
